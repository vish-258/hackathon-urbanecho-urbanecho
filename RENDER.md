# Free Render + Supabase deployment

**Live application: [UrbanEcho](https://urban-echo-uz15.onrender.com/app).** Deployed revision `a7b8907` passed public-access verification on 10 October 2026. The published SIMULATED location opens directly without sign-in; administrator changes still require the private deployment `ADMIN_TOKEN`. The cloud has its own fresh dataset, including one clearly labelled **SIMULATED** verification location/device, six synthetic recordings and one resolved incident; local data and device credentials were not migrated. The first visit after idle sleep can take about a minute.

This package runs the API, measurement worker and incident classifier together on one **free Render web service**. A dedicated free Supabase project stores PostgreSQL/PostGIS data and immutable originals in a private Storage bucket. The service's `/tmp/urbanecho-audio-cache` is disposable; it is never the only copy of an accepted recording. No local database, recording or device credential is copied to the cloud.

This is a small demonstration deployment. Render sleeps after 15 minutes without incoming traffic; waking can take about a minute, and background processing stops while asleep. Its free instance has 512 MB RAM and 0.1 CPU, so classification and bursts of uploads can be slow. Supabase Free currently includes 500 MB database space, 1 GB Storage and 5 GB uncached egress; inactive projects can pause after a week. Originals are never automatically deleted to hide a quota problem. These limits make the free deployment unsuitable for guaranteed continuous monitoring. See [Render Free](https://render.com/docs/free), [compute plans](https://render.com/docs/compute-plans) and [Supabase pricing](https://supabase.com/pricing).

## Create the dedicated project

1. Create a new Supabase Free project solely for Urban Echo, preferably in Singapore. Keep its database password private. Disable the **Data API** and automatic exposure of new tables. Urban Echo uses SQL connections and Storage; it does not need the Data API.
2. Create the **private** Storage bucket `urbanecho-originals`. Do not add public read/write policies. The server uses the project's service-role key; never give that key to browsers or devices.
3. Use the connection dialog's **shared session pooler**, port **5432**. Copy its hostname and project reference. Transaction pooling on port 6543 is rejected. Leave PostGIS uninstalled; bootstrap installs it in `extensions` and refuses an existing installation in `public`.

See [Supabase SQL connections](https://supabase.com/docs/guides/database/connecting-to-postgres), [PostGIS](https://supabase.com/docs/guides/database/extensions/postgis), and [API access controls](https://supabase.com/docs/guides/api/securing-your-api).

## Create the free web service

Use the repository's `render.yaml` Blueprint, or select Docker with `deploy/render/Dockerfile`, repository root as build context, Singapore region, **Free** instance, and `/health/ready` health check. Automatic deployment is off so publishing remains deliberate. No persistent disk, paid worker, separate database, or paid pre-deploy command is required.

Provide these private Render environment values:

| Variable | Value |
| --- | --- |
| `SUPABASE_DB_PASSWORD` | New project's database password |
| `SUPABASE_POOLER_HOST` | Session pooler hostname from Supabase |
| `SUPABASE_PROJECT_REF` | Project reference |
| `SUPABASE_URL` | Project HTTPS origin |
| `SUPABASE_SERVICE_ROLE_KEY` | Private server service-role key |
| `APP_DB_PASSWORD` | Fresh random secret, at least 32 characters; generated by Blueprint |
| `ADMIN_TOKEN` | Separate fresh random secret, at least 32 characters; generated by Blueprint |

The Blueprint sets `APP_DB_USER=noise_app`, `BOOTSTRAP_FRESH_SUPABASE=true`, the private bucket name, `LOCAL_BROWSER_ACCESS=false`, `AUDIO_STORAGE_BACKEND=supabase`, `MIGRATION_SEARCH_PATH=public,extensions`, and small per-process database pools. If setting up manually, copy those values too. `PORT` comes from Render. The Dockerfile enables incident classification and includes the verified model.

Passwords are escaped when the launcher constructs TLS-protected connection URLs. You may instead supply explicit `DATABASE_URL` and `MIGRATION_DATABASE_URL`, both using `postgresql+psycopg`, distinct users and the same database endpoint; include `sslmode=require` or verified TLS. The restricted username is `noise_app.<project-ref>` through the session pooler, and the privileged username is `postgres.<project-ref>`.

## Startup and access

Before opening the public port, the launcher serializes database preparation with an advisory lock. With explicit fresh-project bootstrap enabled, it creates a missing restricted role only when the public schema is empty. It never resets an existing role's password and refuses unrelated schema objects or an elevated application role. It revokes public/Data API access, applies migrations with the privileged credential, then checks those permissions again. Migration grants preserve the application's append-only history restrictions.

Startup verifies that the Storage bucket exists and is private. It then starts all three processes as UID/GID 10001 with the migration credentials and bootstrap fields removed from their environment. Any unexpected child exit stops the whole service. Existing local filesystem and Railway deployments retain their separate launchers and defaults.

Open the assigned HTTPS Render URL at `/app`. For a public demo, set `PUBLIC_DEMO_LOCATION_ID` to the UUID of one deliberately selected demonstration location. That publishes its location/device metadata, readings, incidents, saved reports and audio for anonymous read-only use; only choose data intended for public viewing. Other locations remain private. Leave this setting unset to require sign-in at entry. Use **Admin sign in** and `ADMIN_TOKEN` to provision devices, change settings or generate reports. Never publish administrator or Storage credentials in a submission link.

## Public demo access

`GET /app/access` lets the browser open the configured public location automatically. Every supported public list applies its location filter before pagination, and detail/playback requests reject records belonging to other locations. Live events use the same location scope. The frontend hides mutation controls for visitors, while backend administrator dependencies continue to enforce write protection. Neither the administrator token nor the Supabase key is sent to anonymous browsers. The current hosted fixture is the explicitly published SIMULATED location; local recordings remain separate.

Public entry was verified on hosted revision `a7b8907` with no credentials: one published location, six original downloads with matching SHA-256 checksums, the resolved incident and nonprovisional analysis, revision-bound six-second audio playback, saved-report/recording reads, and rejection of anonymous report generation. A fresh browser load opened the incident directly in **Public demo** mode and loaded its audio. Local verification passed all 182 Node tests and 167 distinct backend checks across the focused public-access, auth, application, events, reports, recordings and incident-evidence runs; the final public-access/events run passed 41 tests. All integration checks used disposable PostGIS databases.
